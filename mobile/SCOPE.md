# Bramble Mobile — Scope

Status: prototype on `feature/mobile-wallet` (2026-09-24). iOS builds and passes its unit and
mainnet UI suites on the simulator; Android is written but not yet built in CI.

## Goal

Ship Bramble on iOS and Android with the same key custody, vault format, network catalog, and
design system as the browser extension, using **Krusty KMS in Rust** as the shared middleware
instead of its WASM build. Native UI per platform (SwiftUI, Jetpack Compose); one Rust core.

## Architecture

```
            SwiftUI app                         Compose app
   (screens, URLSession, Keychain/SE)   (screens, HttpsURLConnection, Keystore)
                 │  UniFFI (Swift)                    │  UniFFI (Kotlin/JNA)
                 └───────────────┬────────────────────┘
                        bramble-core  (mobile/core, Rust)
     kms.rs      → krusty-kms =0.11.0 (same release as @starknetfoundation/krusty-kms-wasm)
     vault.rs    → EncryptedEnvelope v3, byte-compatible with the extension
     wallet.rs   → WalletCore: lifecycle + key custody; phrase never crosses FFI except backup/reveal
     networks.rs → generated/networks.json  (rendered from wallet-model/networks)
     rpc.rs      → sans-IO JSON-RPC: core builds requests and judges responses; host moves bytes
```

What is reused from the extension, and how drift is prevented:

| Shared piece | Source of truth | Mobile copy | Drift gate |
| --- | --- | --- | --- |
| Wallet crypto | Krusty KMS 0.11.0 | `krusty-kms` crate, pinned `=0.11.0` | `tests/conformance/mobile-generated.test.ts` compares the Cargo pin to the npm pin |
| Derivation / addresses / signatures | extension `deriveAccount` + WASM | `kms.rs` | `mobile/core/tests/fixtures/extension-parity.json`, written by the extension's real path, asserted in Rust and Swift tests, re-checked in `bun run check` |
| Vault envelope | `vault/src/encrypted-store.ts` | `vault.rs` | Rust test opens an envelope the extension sealed |
| Skins, scale, motion, springs, shadows | `ui-kit/src/theme/*` | `BrambleTokens.generated.{swift,kt}` | generated by `bun run mobile:assets`; byte-compared in `bun run check` |
| Brand mark | `ui-kit/src/components/brand-mark.ts` | iOS vector asset, Android vector drawable | same generator + test |
| Networks, RPC endpoints, default tokens | `wallet-model/src/networks/networks.ts` | `core/generated/networks.json` | same generator + test |
| Felt grammar, explorer URLs | `wallet-model/networks` | `felt.rs`, `explorer_account_url` | unit tests mirror the TS cases |

## Security posture (implemented)

- **Keys stay in Rust.** Private keys are derived per call into Krusty's zeroizing `SecretFelt`
  and never returned. The phrase is held in a zeroize-on-drop payload for the unlocked session
  only; it crosses FFI only at creation (to back it up) and on a password-rechecked reveal.
- **Fail closed.** No fallback crypto; every Krusty output is re-validated (curve-order range,
  non-zero felts); errors carry an operation name, never input text.
- **Vault at rest.** PBKDF2-SHA-256 600k → AES-256-GCM, additional data binds scope, lineage and
  commit; tampered iteration counts are refused. Atomic write-then-rename. iOS: Application
  Support, `FileProtectionType.complete`, excluded from backup. Android: `noBackupFilesDir`,
  `allowBackup=false`, data-extraction rules exclude every domain.
- **Session.** Leaving the foreground locks and zeroizes (iOS `scenePhase`, Android
  `ProcessLifecycleOwner`). iOS covers the app-switcher snapshot; Android sets `FLAG_SECURE`.
- **Phrase display.** Hidden while the iOS screen is recorded/mirrored; screenshot warning;
  `privacySensitive`; no autocorrect, capitalisation or keyboard learning on phrase/password fields.
- **Network.** Sans-IO: no TLS or HTTP code in Rust. HTTPS only (ATS / `usesCleartextTraffic=false`),
  ephemeral URLSession. An endpoint is trusted only after `starknet_chainId` proves the chain;
  responses must answer their request id, are size-bounded, and u256 limbs are range-checked.
- **Clipboard.** Addresses only, local-only and expiring after two minutes on iOS.
- **Supply chain.** Every Rust dependency pinned exactly with a committed `Cargo.lock`; builds use
  `--locked`. Gradle and Android dependencies pinned exactly.

## Phases

**Phase 0 — prototype (this branch).** Create/import, backup, unlock/lock, multiple accounts,
mainnet/Sepolia, live STRK/ETH balances, receive with QR, explorer, reveal phrase, delete
wallet. iOS verified; Android source only.

**Phase 1 — sendable wallet.**
1. Android in CI: Gradle wrapper, NDK build via `build-core-android.sh`, instrumented parity test.
2. Transactions in the core: invoke v3 hashing (`krusty_kms::compute_invoke_v3_hash`), fee
   estimation and nonce as sans-IO RPC, OZ deploy-account; Send screen with review. Port the
   extension's review rules rather than re-deriving them.
3. Biometric unlock: a random vault key wrapped by a Secure Enclave / StrongBox key that needs
   user presence; the password stays the recovery path. Persisted wrong-password back-off.
4. CI job for `cargo test --locked`, clippy, `cargo deny`, and the iOS unit suite.

**Phase 2 — feature parity.** Token list and prices, activity history, Argent/Braavos discovery,
multisig, WalletConnect in place of the injected provider, STRK20 privacy (viewing keys stay in
the core, as the extension's AGENTS.md rules require), Ledger over BLE.
- *Done (portfolio-activity, iOS verified; Android source only, uncompiled):* fiat prices in
  USD/EUR/GBP with the hero total and 24h change, per-token fiat and change, tracked/hidden
  tokens with "Manage tokens · N not shown", add by contract, find held tokens, token chart, and
  an Activity tab fed by the Starkscan lane or the RPC scan with explorer links. The saved-data,
  prices-offline, balance-failed and history-unavailable states match the extension's stories.
  All request building and response judging is in the core, byte-checked against the extension
  by `bun run mobile:parity` (`mobile/docs/portfolio-activity.md`).

**Phase 3 — release.** Store listings, App Store privacy labels / Play data safety, external
audit of the core and FFI surface, reproducible builds, crash reporting without PII.

## Decisions to make

- **Vault portability.** Mobile uses the extension's envelope but its own payload
  (`bramble.mobile.vault.v1`). Should phase 2 adopt the extension's vault schema v4 so an
  encrypted export moves between devices?
- **UniFFI (Mozilla) as a new dependency.** It generates both bindings from one Rust surface and
  removes hand-written `unsafe` FFI. The alternative is a hand-written C ABI like Krusty's
  `crates/ffi-mobile`.
- **Upstream vs. local core.** Krusty's `feat/mobile-pq-signer` branch deliberately keeps its
  mobile ABI public-material-only. A software-key wallet core belongs here, not in that crate —
  confirm with the Krusty maintainers.
- **Minimum OS.** iOS 17 (for `@Observable`) and Android 9 / API 28 are assumed.

## Known limits

- Swift/Kotlin `String` passwords and the phrase shown at backup can't be zeroized by the host.
  The Rust side zeroizes its copies, but serde's parse buffers aren't guaranteed to be wiped.
- Unlock back-off is not persisted yet (Phase 1.3).
- Send is visible but disabled.
