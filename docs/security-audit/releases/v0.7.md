## Executive summary

The v0.7 review followed the new NFT path from untrusted indexer and contract data through
ownership proof, metadata resolution, rendering, review, signing, and broadcast. It also checked
the dapp approval-surface preference, account-scoped refresh behavior, the companion terminal
request flow, test organization, and privileged GitHub workflow changes.

No fund-loss or security-bypass finding remains open in this release scope. NFT transfer is now a
separate review and confirmation flow. Both stages rebuild and verify the same standard-specific
call, re-prove ownership for the active account and network, and block an address-poisoning match
before signing. ERC-721 and ERC-1155 compatibility no longer depends on one contract naming
convention.

Metadata stays display-only and untrusted. Inline data is bounded and parsed locally. Remote
metadata is fetched only for an explicitly watched token, through a public-HTTPS-only,
credentialless, no-referrer, redirect-rejecting, size-capped boundary. An unsolicited airdrop
cannot contact its metadata or image host merely because the wallet unlocks or paints the gallery.

## Reviewed trust boundaries

- Indexer candidate list → bounded on-chain ERC-721 owner / ERC-1155 balance re-proof.
- Contract `token_uri` / `tokenURI` / `uri` result → validated Cairo `ByteArray` decoder.
- Data, IPFS, and HTTPS metadata → bounded JSON normalization → escaped side-panel rendering.
- Watched versus unsolicited collectible → permission to fetch remote metadata or reveal artwork.
- NFT detail form → review report → exact matching confirmation → signer → broadcast.
- Active account/network generation → cached artwork and asynchronous refresh results.
- Dapp user gesture → popup or side-panel opening → authoritative background approval queue.
- Release branch source → read-only build runner → inert artifact → hosted release publisher.

## Assurance conclusions

### Ownership and standard detection

The wallet tries Starknet ERC-721 `owner_of`/`ownerOf` and then ERC-1155
`balance_of`/`balanceOf`, validating felts and both uint256 limbs. RPC transport faults retain
normal endpoint failover; malformed or unsupported contract responses fail closed. Indexer results
are capped, checked in fixed-size batches, and dropped when ownership cannot be re-proven.

Manual add, detail review, and final transfer each resolve the active account and network and
re-prove a positive holding. Watched collectible preferences are not treated as an ownership
credential.

### Metadata and image privacy

Metadata URI responses are length- and shape-checked Cairo `ByteArray` values. The resolver accepts
bounded percent-encoded or Base64 JSON data URIs and maps `ipfs://` through the fixed gateway.
Remote fetches omit credentials, send no referrer, reject redirects, cap declared and streamed
response bytes, and reject local/private destinations. Text, URLs, and at most 32 attributes are
normalized before they cross into the view model.

Unsolicited indexer candidates are not metadata-hydrated in the background and render without a
remote `<img>`. Explicitly watched collectibles may load their art after ownership proof, and an
unwatched collectible reveals its image only after the user opens its detail view. Image elements
also use `referrerpolicy="no-referrer"` and degrade to the local placeholder on error.

### Review and broadcast integrity

Review and submission call one shared preparation path. It detects ERC-721 versus ERC-1155,
constructs `transfer_from` or `safe_transfer_from`, verifies the call, and derives the decoded
summary and risk flags. The UI records a confirmation key over contract, token, network, and
recipient; editing any field invalidates it. A failed fee estimate or address-poisoning flag cannot
unlock confirmation. The background repeats ownership and poisoning checks at submission, so UI
state is not authoritative.

### Approval surfaces and async state

The chosen approval surface changes where a request is displayed, not whether it is authorized.
Only allowlisted, origin-validated request types can trigger it; silent reconnects do not open UI;
popup failure falls back to the side panel; and browser UI failure never settles or approves the
background request.

Watched artwork loads in a dedicated high-priority lane after unlock. Duplicate loads coalesce,
mutations invalidate in-flight cache entries, and account/network changes clear NFT lanes and
discard stale generation results before repaint. These optimizations do not bypass ownership or
metadata checks.

## Residual boundaries

Opening or explicitly watching a collectible permits its public remote image host to observe the
requesting IP address; the wallet removes referrer and credential data but cannot provide an
anonymizing proxy. RPC nodes, configured indexers, gateways, browsers, and remote metadata hosts
remain third-party availability and privacy boundaries.

Non-standard contracts may still be unreadable even when an explorer applies custom heuristics.
The wallet intentionally fails closed rather than guessing calldata or ownership. Explorer
indexing is independent: a valid on-chain data URI may display in Bramble while an explorer has
not indexed its attributes.

The mainnet MC Punks contract is an unaffiliated interoperability fixture. Its terminal mint page
does not make the contract or artwork part of the extension package, and the release review is not
a third-party audit of that Cairo contract.

This assurance record establishes controls at the scoped baseline; it is not an
absence-of-defects guarantee. Any change to NFT ABI detection, metadata URL policy, rendering
consent, review/confirmation identity, ownership re-proof, or release authority requires renewed
focused review.
