# v0.9 deep audit — informational findings

Continuation of the [v0.9 deep adversarial audit](../v0.9-deep/). Method, verification, and
residual boundaries are defined in the parent document. Split out of the
[low findings](../v0.9-deep-tail/) when that document reached its size budget.

### MCW-V09-130

- **Severity:** Informational  |  **Area:** consistency  |  **Status:** Resolved
- **Location:** `src/shared/json.ts:281`

**Mechanism.** This aggregates the consistency debt that underlies several higher-ranked findings rather than
listing 27 separate items. isSafeDecimals's doc says "The one shared bound — do not re-derive the
`36` literal locally" (src/shared/json.ts:281-287); the 0..36 bound is written out again at
src/popup/responses.ts:210-213, src/popup/app …

**Impact.** No live exposure today — I traced each and in every case either the strict validator sits on the
attacker-facing side, or the value cannot be produced, or structured-clone serialization empties the
leaked object.

**Remediation (shipped).** Each named concept now has one definition and the surfaces that carried a
private copy answer to it: the token symbol, decimals, base-units, and human-amount grammars and the
`isOwnDataProperty`/`hasOnlyArrayEntries` boundary guards moved into
`packages/foundation/core/src/json.ts`; the uint256
limb join, the felt grammar, the unlimited-allowance cut-off, the chain-id form, the token-config id,
and the custom-network URL and label policies each resolve to a single exported helper.

The last step is the one a first pass missed, and it is the sharpest, because the helper's own doc
comment already forbade the alternative: `isStarkPrivateKey` says to use it — *never*
`isNonZeroStarkFieldElement` — for a raw signing key, since the ~2^126-wide gap `[n, P)` holds field
elements that are not keys and a signer reduces one mod `n`, signing for a scalar nobody recorded. The
raw-key import obeyed that; the vault's stored `SigningKeyRef`, the KMS keypair result, `signStarkHash`,
and the STRK20 viewing-key derivation did not, so a scalar refused at the import door was still
storable and still signable underneath it. All four now apply the shared predicate, and
`STARK_CURVE_ORDER` is exported so the conformance sweep can build a value inside the gap rather than
writing the constant out a second time.

**Verification.** `tests/conformance/shared-helper-single-source.test.ts` and
`tests/conformance/shared-grammar-single-source.test.ts` pin each concept across the surfaces that must
agree about it, with literal expectation tables rather than assertions comparing an implementation to
the predicate it calls — a private copy passes its own tests and fails these. The signing-scalar suite
first proves the gap is reachable (so the cases cannot be vacuous), then drives a gap value through the
import parser, the vault validator, and all four KMS entry points.

### MCW-V09-131

- **Severity:** Informational  |  **Area:** supply-chain  |  **Status:** Resolved
- **Location:** `scripts/check-extension-manifest.ts:173`

**Mechanism.** Two independent holes in the build-gate layer, both of which are exactly what a single negative test
would have caught. (1) scripts/check-extension-manifest.ts applies its HTML-integrity check —
exactly one script tag, matching the expected packaged module, no `on<event>=` attribute, no
javascript: URI — to only two pages: sidep …

**Impact.** The repository's gates give false assurance in two places. A reader of check-extension-manifest.ts
concludes every shipped page is integrity-checked and every capability is manifest-declared; both
are false for 3 of 5 pages, so an inline script or an onload= h …

**Remediation (shipped).** `PACKAGED_PAGES` declares all five shipped pages — `sidepanel.html`,
`onboarding.html`, `popup.html`, `ledger-grant.html`, and the sandboxed page — each with the module it
is expected to load, and the integrity check runs over every one. Two scans close the declaration
itself in both directions: a packaged page absent from `PACKAGED_PAGES` fails, and a manifest-named
page absent from it fails, so the gate can no longer be complete-looking and partial.

The Actions half is now derived rather than listed. `scripts/workflow-inventory.ts` owns one `uses:`
extractor and one pin rule, shared by the workflow security policy and `check:files` so neither gate
can be the looser of the two, and it reads every file in `.github/workflows` instead of a hard-coded
path list — a directory holding no workflow, or holding a file that is not one, throws rather than
reporting success over nothing. The extractor reaches the block step, the bare key, the inline map, the
flow sequence, and the quoted key; a `uses:` it cannot resolve to exactly one reference on the same
line fails closed. Local reusable-workflow references (`./.github/workflows/…`) are allowed
explicitly, because they carry no SHA to pin and refusing them would have been the reason to loosen the
rule instead.

**Verification.** `tests/scripts/extension-packaged-pages.test.ts` drives each page through the
integrity checker with an injected inline script, an `onload=` handler, and a `javascript:` URI;
`tests/scripts/workflow-action-pinning.test.ts` covers every `uses:` spelling including the ones the
old regex silently skipped; and `tests/scripts/workflow-inventory.test.ts` pins that `.yaml` is policed
like `.yml` and that an empty or foreign directory throws.
