# v0.10.1 security audit and remediation

Private working report. No public disclosure or deployment is performed by this audit.

## Baseline and method

Scope: [v0.10.1-scope.md](v0.10.1-scope.md). Baseline:
`41ad4f8353c2171e7a94092968768442db8a450c`, released as v0.10.1.
Work is committed locally to `audit/v0.10.1-security`.

The scope review now accounts for all 59 requested bullets in the
[item-by-item coverage ledger](v0.10.1-coverage.md). This is a source and regression-test
audit, not a certification or a claim that every dependency line was manually reviewed.
It combines entry-point enumeration, manual security-boundary tracing, adversarial tests, the
repository's complete automated gates, dependency advisory verification, packaged-browser
E2E, and artifact checks. Historical audits provide context only.

## Architecture and trust assumptions

The MV3 extension is the custody application. Untrusted website traffic crosses the
page-to-content-script bridge, then browser-authenticated runtime sender checks, then
background permissions/approval/session boundaries. The background owns vault access and
selects either the pinned Krusty signer or the Ledger queue. UI pages render permissioned
responses. The in-page provider is public code and is not a trusted authenticator.

Terminal is a separate browser application with serverless API handlers under
`apps/terminal/api`. It delegates custody to the connected wallet. Its server retains the
paymaster credential. Website/UI Lab are separate build surfaces; website deployment
uses Wrangler. None is a substitute for the background's signing authorization.

RPCs, quote APIs, discovery/prover/paymaster services, price feeds, and metadata providers
are external inputs. Pinned SDKs, deployed account/pool/executor contracts, browser storage
isolation, and Ledger firmware remain trust dependencies. Chain-id probes do not prove
that a malicious RPC reports authentic chain state. Simulation is not a promise of final
execution state. A page controlling its own origin can always deceive its own UI.

## Findings and fixes

| ID | Assessment | Finding | Remediation and evidence |
| --- | --- | --- | --- |
| V0101-01 | Low, availability | Optional analytics randomness failure could reject a privacy operation and leave its serialized queue unreleased. | `05df6142`: metadata setup is contained inside the queue's cleanup boundary; failures omit the flow identifier. Two consecutive operations succeed with a throwing randomness boundary. |
| V0101-02 | Low, privacy | Opt-out during an awaited installation-id lookup could still emit analytics metadata. | `05df6142`: recheck consent after lookup and before attaching headers. Paused-storage regression fails before the fix and passes afterward. This does not cancel a request already sent. |
| V0101-03 | Low, defensive session hardening | A delayed restore snapshot could overwrite a newer lock or unlock. | `954094ae`: bind restoration to the original generation; refuse stale reads and increment generation on restoration. Lock/replacement tests fail before and pass after. Production startup currently serializes runtime initialization behind restore, so a website-triggered exploit is not established. |
| V0101-04 | Medium, metadata confidentiality | Pending origin-grant, connected-sites, account and permission reads could outlive session revocation and return stale information. | `3caf6cab`, `bd8ee183`: check the original session after awaited reads and before returning provider metadata. Nine deterministic cases cover preferences/grant/sites reads, replacement sessions, and direct provider queries. Existing reconnect and connected-sites tests continue to pass. `31abd8db` also checks deployment discovery after grant/RPC waits. No private-key disclosure was demonstrated by this finding. |
| V0101-05 | High upstream advisory; wallet-runtime exposure not established | Website tooling resolved `sharp@0.35.2`, affected by GHSA-rgj7-g3m4-5g8c. | `6e4c259e`: exact `sharp@0.35.4` override and a strict configuration assertion. Latest Wrangler still pinned the affected version at review time. Dependency audit changes from failure to success; website build and Wrangler dry run pass. Remove the override only once the parent resolves a patched version. |
| V0101-06 | Medium, approval/session authorization | Claiming removes an approval from the queue before awaited checks, so clearing the queue on lock did not revoke claimed work. A connect executor waiting inside the state coordinator could also adopt a replacement unlock. | `31abd8db`, `8b83a9e0`: check claim-time authority and give every executor a session view that permanently refuses later credentials after revocation. Watch-asset lock/replacement and delayed-connect regressions fail before and pass after; rejected operations perform no write/grant. |
| V0101-07 | Medium, signing/disclosure authorization | Typed-data execution captured signer authority after asynchronous grant reads; lock followed by unlock with the same credential allowed a signature from the replacement session. Private account resolution duplicated the stale-read pattern. | `65070d84`: capture typed-signing authority before reads and reuse the guarded origin resolver for private account resolution. Four typed-signing cases and four private grant/preference cases exercise lock/replacement. No signer is called after rejection. The claim-bound session view also protects late helper construction. |
| V0101-08 | High potential loss under a hostile route response; no on-chain loss demonstrated | Private-swap UI advertised a 0.50% slippage limit while validating only outer action fields. Embedded executor calls could contain different amounts, beneficiary, fees, calls or a zero minimum. | `3d397e17`: decode exactly approve + pinned-router multi_route_swap, bind amount/spender/tokens/beneficiary, reject unrequested fees and hidden calls, and show the enforced minimum. Twenty pure adversarial cases plus client handoff tests pass. Executor provenance is separately contained by V0101-10. |
| V0101-09 | Medium, server credential capability | Gateway checked the pool target and fee mode but accepted another transaction type, extra invoke fields or another pool selector before attaching the paymaster credential. | `75f06fcb`: require the apply_action union, reject extra transaction/call fields and pin apply_actions selector. Three substituted-envelope tests prove no upstream fetch occurs; the pinned SDK envelope is still accepted. Upstream rejection might independently prevent exploitation, but is not relied on. |
| V0101-10 | High potential loss under a hostile executor response; contained | The private route response also selected the executor receiving withdrawn tokens. Calldata checks cannot make an arbitrary contract execute those calls honestly. An independent deployment/source/upgrade-policy pin was not established. | `7c2e70f5`: client and server planning now fail closed with a null reviewed executor anchor; the UI explains that private swaps are unavailable. Production-gate tests prove no route fetch occurs; test-only pins exercise the future enabled path and reject substituted executor addresses. Re-enabling requires independently reviewed deployment evidence. Core private balances/transfers are not disabled. |

The [upstream sharp advisory](https://github.com/advisories/GHSA-rgj7-g3m4-5g8c)
affects processing untrusted image inputs and identifies 0.35.4 as patched. The observed
path is website development/deployment tooling through Wrangler and Miniflare, not the
extension package. No adversarial image was executed.

## External evidence still needed

- Deployed gateway/paymaster firewall and abuse limits, credential permissions and rotation.
- Operator proof of the documented analytics pseudonymization and 90-day retention policy.
- Independent cryptographic/protocol review of upstream KMS/Privacy SDK, account contracts,
  and deployed pool/executor economics; physical Ledger/browser-platform assurance.
- Independently reviewed executor address, source/deployment provenance and upgrade policy
  before re-enabling private swaps. The current branch refuses that path.

These limits remain explicit rather than being labeled passed by local tests. The fixes
on this branch are not present in the already published v0.10.1 artifact until released.

`/tmp/audit-typed-session-before.log`, `/tmp/audit-private-before.log`,

The pinned AVNU SDK `4.2.0` implementation was inspected for its Cairo-1 executor
serialization and paymaster wire envelope. The upstream
[private-transaction integration guide](https://github.com/avnu-labs/paymaster/blob/main/docs/private-transactions.md)
was consulted for protocol context; its example is not deployment provenance or evidence
that an arbitrary executor is safe. No live proof, signing request or transaction was sent.

A signing-card assurance that “signing does not move funds” was replaced with an explicit
warning that signatures can authorize transfers/account access, and its rendering test was
updated. Gateway documentation now distinguishes exact-origin CORS from the separately
accepted privileged-extension Fetch Metadata shape; neither authenticates non-browser clients.

PR preparation extracted the render-only `PrivateSwapReview` component to keep the
Privacy screen below the 500-line cap. Terminal checks/build and the full repository
check were rerun for that extraction; signing and submission behavior are unchanged.
